# Code Generation Strategies

This document describes the five strategies used in `run_code.sh` and their detailed flows.

---

## 1. Simple

**Entry point**: `code/simple.py:run_simple()`

**Parameters**: `max_iters=1`, `pass_at_k=1`, no iterative improvement.

### Flow

For each problem in the dataset:

1. **Load pitfall insights (optional)**: If `--use_mistakes` is enabled:
   - If `mistake_json_file` is provided (pre-generated pitfall JSONL): extract `mistake_json_file[i]['pitfall']`
   - If `pitfall_agent` (LoRA CodePitfallAgent) is available: call `pitfall_agent.generate(prompt, temperature=0.1)`
   - Otherwise: call `gen.generate_pre_insights(prompt)` to generate insights on-the-fly

2. **Generate code**: Call `gen.func_impl(prompt, model, "simple", mistake_insights=refined_insights, temperature=0.2)`

3. **Evaluate**: Execute the generated code against test cases
   - HumanEval: `exe.evaluate(entry_point, cur_func_impl, test_code, timeout=6)`
   - LiveCodeBench: `exe.evaluate_livecodebench(identifier, cur_func_impl, test_cases, timeout=20)`
   - If passing, mark as solved and break

4. **Retry up to pass_at_k times**: If not solved, regenerate and re-evaluate

5. **Log results**: Write item with `is_solved`, `solution`, `cost`, etc. to JSONL

### What is sent to the LLM

The key function is `gen.func_impl()` in `generators/py_generate.py:PyGenerator.func_impl()`, which calls `generic_generate_func_impl()` in `generators/generator_utils.py`.

#### Case A: Without mistake insights (`mistake_insights=None`)

For chat models:

```
[System]:
"You are an AI that only responds with python code, NOT ENGLISH. You will be given a function signature and its docstring by the user. Write your full implementation (restate the function signature).
Use a Python code block to write your response. For example:
```python
print('Hello world!')
```"

[User]:
{func_sig}   <-- the raw problem prompt (e.g. HumanEval function signature + docstring)
```

For completion models:

```
# Write the body of this function only.
{func_sig}
Use a Python code block to write your response. For example:
```python
print('Hello world!')
```
```

#### Case B: With mistake insights (`mistake_insights` is provided)

For chat models:

```
[System]:
"You will be given a function signature and its docstring, along with a set of summary hints that highlight common pitfalls and several flawed implementation examples. Based on these hints and flawed examples, write a correct implementation of the function. You are an AI that responds only with Python code—no English. Restate the full function signature, and provide the complete implementation.
Use a Python code block to write your response. For example:
```python
print('Hello world!')
```"

[User]:
{mistake_insights}
 [func signature]: {func_sig}
```

Here `mistake_insights` contains pitfalls and flawed implementations generated by the pitfall agent or pre-generated JSONL, typically structured as:

```
[Pitfalls]:
1. **Pitfall description 1**
2. **Pitfall description 2**
...

[Flawed Implementations]:
```python
def func_v1(...):  # BUG: description
    ...
```

For completion models (without mistake insights):

```
# Write the body of this function only.
{func_sig}
Use a Python code block to write your response. For example:
```python
print('Hello world!')
```
```

**The LLM output is then parsed** via `parse_code_block()` to extract the Python code block from the response.

## 2. Reflexion

**Entry point**: `code/reflexion.py:run_reflexion()`

**Parameters**: `max_iters=5`, `pass_at_k=1`

### Flow

For each problem:

1. **Generate test cases**: Use visible tests, or synthetic tests generated by `gen.internal_tests()`

2. **First attempt**: Generate code with `gen.func_impl(prompt, model, "simple", temperature=0.2)` → Execute on intermediate tests → Get feedback

3. **If solved**: Evaluate on real (hidden) test cases → Exit early

4. **Iterative improvement loop** (up to `max_iters=5`):
   - **Self-reflection**: Call `gen.self_reflection(cur_func_impl, cur_feedback, model)` to generate a reflection on why the code failed
   - **Regenerate**: Call `gen.func_impl(prompt, model, "reflexion", prev_func_impl, feedback, self_reflection, temperature=0.2)` to generate improved code
   - **Evaluate**: Execute on intermediate tests → Get new feedback
   - **If solved or last iteration**: Evaluate on real test cases → Exit

### What is sent to the LLM

#### Self-reflection generation

```
[System]:
"You are a Python programming assistant. You will be given a function implementation and a series of unit tests. Your goal is to write a few sentences to explain why your implementation is wrong as indicated by the tests. You will need this as a hint when you try again later. Only provide the few sentence description in your answer, not the implementation."

[User]:
{PY_SELF_REFLECTION_FEW_SHOT}

[function impl]:
```python
{cur_func_impl}
```

[unit test results]:
{feedback}

[self-reflection]:
```

#### Reflexion code generation

```
[System]:
"You are an AI Python assistant. You will be given your past function implementation, a series of unit tests, and a hint to change the implementation appropriately. Write your full implementation (restate the function signature).
Use a Python code block to write your response."

[User]:
{PY_REFLEXION_FEW_SHOT_ADD}  <-- the "add" few-shot example

[Assistant]:
```python
{prev_func_impl}
```

[User]:
[unit test results from previous impl]:
{feedback}

[reflection on previous impl]:

[Assistant]:
{self_reflection}

[User]:
[improved impl]:
{func_sig}
```

## 3. DoT (Diversity of Thought)

**Entry point**: `code/dot.py:run_dot()`

**Parameters**: `max_iters=5`, `pass_at_k=1`

### Flow

For each problem:

1. **Generate test cases**: Use visible tests or synthetic tests

2. **First attempt**: Generate code with `gen.func_impl(prompt, model, "simple")` → Execute → Get feedback

3. **Iterative improvement loop** (up to `max_iters=5`):
   - **Diverse reflections**: Call `gen.self_reflection_diverse_oneshot(cur_func_impl, cur_feedback, model, diverse_reflections)` to generate **multiple diverse reflections** in one shot (split by `\n\n`)
   - Filter reflections (length > 10 chars)
   - **For each reflection** (up to 2):
     - Generate new code with `gen.func_impl(prompt, model, "reflexion", prev_func_impl, feedback, self_reflection=reflection, ref_chat_instruction='dot')`
     - Execute on intermediate tests → Compute **reflection score** (number of passing tests)
   - **Weighted sampling**: Use `random.choices(weights=reflections_scores)` to select one implementation as the next starting point
   - Continue to next iteration

### What is sent to the LLM

#### Diverse reflection generation (one-shot)

```
[System]:
"You are a Python programming assistant. You will be given a function implementation, unit tests, and previously generated reflections.
Write 3 unique and diverse reflections to fix the problem. Each reflection should follow this structure:

Problem: {a terse description of the identified problem}.
Fix: {proposed fix or hint to fix the identified problem}.

Ensure your reflections are accurate and leverage previous reflections to avoid repetition.
Aim for diversity in your explanations while prioritizing the correctness of your hints.
Add "\n\n" at the end of each proposed reflection."

[User]:
{PY_DIVERSE_REFLECTION_FEW_SHOT}

[function impl]:
```python
{cur_func_impl}
```

[unit test results]:
{feedback}

[Previously generated reflections:]:
{reflections_history}

[self-reflection]:
```

#### Reflexion code generation (DoT variant)

Uses `PY_DoT_CHAT_INSTRUCTION` as system prompt instead of `PY_REFLEXION_CHAT_INSTRUCTION`:

```
[System]:
"You are an AI Python assistant. You will be given your previous implementation of a function, a series of unit tests results, and your self-reflection on your previous implementation. ALWAYS WRITE your full implementation (restate the function signature).
Use a Python code block..."

[User → Assistant → User → Assistant → User]:
(few-shot example → prev_impl → feedback+reflection request → reflection → improved_impl request)
```

## 4. DoT-Bank

**Entry point**: `code/dot_bank.py:run_dot_bank()`

**Parameters**: `max_iters=5`, `pass_at_k=1`

### Two-stage mechanism with memory bank

#### Stage 1 (First Pass)

For each problem:

1. Same as DoT: first attempt → diverse reflections → weighted sampling
2. **Memory bank construction**:
   - If the implementation passes intermediate tests: store as `positive_trajectory` (with `prompt_embedding`, `reflection_embedding`, `gen_solution`, `prev_implementation`, `test_feedback`)
   - If it fails: store as `negative_trajectory`
   - Failed problems are collected into `failed_problems` list
3. **Post-processing**: For HumanEval, `_postprocess_impl()` extracts only the target function from the generated code (strips unittest code and main blocks)

After Stage 1, save `first_stage_log.jsonl` and filter failed problems.

#### Stage 2 (Second Pass — Memory-Augmented)

For each failed problem:

1. **Retrieve similar examples** from memory bank:
   - Compute prompt embedding via `get_openai_embedding()`
   - Find top-k closest positive trajectories via cosine similarity (`get_top_k_closest()`)
   - Build few-shot augmented prompt with similar solved examples:
     ```
     Below are similar solved programming examples. Learn their solution style.
     [Example 1]
     Problem: {similar_prompt}
     Solution: {similar_solution}
     Now solve the NEW problem...
     [CURRENT PROBLEM]
     {current_prompt}
     ```

2. **First attempt**: Generate code with memory-augmented prompt

3. **Reflexion iterations**:
   - For each reflection, also retrieve similar trajectory by **reflection embedding similarity**:
     - Find closest positive trajectory whose `reflection_embedding` is similar to the current reflection
     - Compose few-shot reflexion example:
       ```
       Example 1 (Reflexion Improvement):
       [previous solution]: {closest_prev_impl}
       [reflection]: {closest_reflection}
       [improved solution]: {closest_gen_solution}
       ```
   - Inject this few-shot example into the reflexion code generation prompt
   - Execute, score, and weighted-sample as in DoT

4. **Update memory bank** and `second_stage_log.jsonl`

### What is sent to the LLM (Stage 2)

#### Initial code generation (memory-augmented)

```
[System]:
"You are an AI that only responds with python code, NOT ENGLISH. You will be given a function signature and its docstring by the user. Write your full implementation (restate the function signature).
Here are {k} problems and their solutions.

[Problem 1]
```python
{closest_match_prompt}
```
[Solution 1]
```python
{closest_match_gen_solution}
```
"

[User]:
{augmented_prompt}  <-- current problem prompt + similar solved examples
```

#### Reflexion code generation (memory + reflection augmented)

```
[System]:
PY_DoT_CHAT_INSTRUCTION + code_block_instruction

[User]:
{PY_FEW_SHOT}  <-- composed from closest trajectory:
  Example 1:
  [previous impl]: {closest_prev_impl}
  [unit test results]: {closest_test_feedback}
  [reflection]: {closest_reflection}
  [improved impl]: {closest_gen_solution}

[Assistant]:
{prev_func_impl}

[User]:
[unit test results]: {feedback}
[reflection on previous impl]:

[Assistant]:
{self_reflection}

[User]:
[improved impl]: {func_sig}
```

## 5. ParamAgent

**Entry point**: `code/main_param.py` → `code/dot_parametric_with_bank.py:run_dot()`

**Parameters**: `max_iters=5`, `inner_iter=5`, `--use_mistakes`, `pass_at_k=1`

### Two-stage mechanism with memory bank + parametric pitfall knowledge

#### Stage 1 (First Pass with Pitfall-Injected Inner Iterations)

For each problem:

1. **Inner iteration loop** (`inner_iter=5`):
   - For each inner iteration:
     - Get pitfall insights:
       - First iteration (`init_iter=0`): Use low-temperature pitfall (`mistake_json_file[i]['pitfall']` or `pitfall_agent.generate(temperature=0.1)`)
       - Later iterations (`init_iter>0`): Use high-temperature diverse pitfalls (`mistake_json_file[i]['high_temp_pitfall']` or `pitfall_agent.generate(temperature=1.0)`)
     - Generate code with `gen.func_impl(prompt, model, "simple", mistake_insights=refined_insights)`
     - Execute on intermediate tests
     - If passing or last inner iteration: Evaluate on real test cases → If solved, store positive trajectory in memory bank → Break

2. **If not solved after inner iterations**, enter DoT-style diverse reflection loop:
   - Generate diverse reflections using `gen.self_reflection_diverse_oneshot_parametric()` (which includes `mistake_insights` in the prompt)
   - For each reflection (up to 2): Generate improved code → Execute → Score
   - Weighted sample next implementation
   - Update memory bank with trajectory (positive/negative based on test results)
   - Iterate up to `max_iters=5`

3. Store `original_index` for Stage 2 lookup, save failed problems

#### Stage 2 (Memory-Augmented + Pitfall-Injected)

For each failed problem:

1. **Retrieve similar examples** from memory bank (prompt embedding similarity)

2. **Build augmented prompt** with similar solved examples (`_build_augmented_prompt_from_examples()`)

3. **First attempt**: Generate code with `gen.func_impl(augmented_prompt, model, "simple", mistake_insights=...)`
   - Insights come from closest trajectory's `mistake_insights` field or the item's own insights

4. **Reflexion iterations**:
   - Get new pitfall insights (high-temperature from `mistake_json_file` or `pitfall_agent`)
   - Generate diverse reflections with `self_reflection_diverse_oneshot_parametric()` (includes pitfall insights)
   - For each reflection:
     - **Reflection-conditioned retrieval**: Find closest positive trajectory by reflection embedding similarity
     - Compose composed_self_reflection = reflection + `_compose_programming_reflexion_few_shot(closest_traj)`
     - Generate improved code with `gen.func_impl(augmented_prompt, model, "reflexion", ..., self_reflection=composed_self_reflection, ref_chat_instruction='dot', mistake_insights=refined_insights)`
     - Execute → Score → Weighted sample
   - Update memory bank

### What is sent to the LLM

#### Pitfall-injected simple generation (inner iteration)

```
[System]:
"You will be given a function signature and its docstring, along with a set of summary hints that highlight common pitfalls and several flawed implementation examples. Based on these hints and flawed examples, write a correct implementation of the function. You are an AI that responds only with Python code—no English. Restate the full function signature, and provide the complete implementation.
Use a Python code block..."

[User]:
{mistake_insights}
 [func signature]: {func_sig}
```

#### Parametric diverse reflection generation

```
[System]:
"You are a Python programming assistant. You will be given some potential pitfalls and flawed implementations, a function implementation, unit tests, and previously generated reflections.
Write 3 unique and diverse reflections to fix the problem..."

[User]:
[Example]: {PY_DIVERSE_REFLECTION_PARAMETRIC_FEW_SHOT}

[Pitfalls]: {mistake_insights}

[function impl]:
```python
{cur_func_impl}
```

[unit test results]:
{feedback}

[Previously generated reflections:]:
{reflections_history}

[self-reflection]:
```

#### Parametric reflexion code generation (DoT + pitfalls + memory)

```
[System]:
"You are an AI Python assistant. You will be given some potential pitfalls and several flawed implementations for the coding challenge, and given your previous implementation of a function, a series of unit tests results, and your self-reflection on your previous implementation. Try to avoid errors of your previous implementation and the pitfalls. ALWAYS WRITE your full implementation (restate the function signature).
Use a Python code block..."

[User]:
{PY_SELF_REFLEXION_PARAMETRIC_FEWSHOT_FUNC_IMPL}  <-- parametric few-shot with pitfalls+flawed impls

[Assistant]:
{prev_func_impl}

[User]:
{mistake_insights}
[unit test results from previous impl]:
{feedback}

[reflection on previous impl]:

[Assistant]:
{composed_self_reflection}  <-- reflection + memory-retrieved few-shot hint

[User]:
[improved impl]: {func_sig}
```

## Strategy Comparison

| Strategy | Iterations | Diverse Reflections | Memory Bank | Pitfall Knowledge | Stages |
|----------|-----------|--------------------|-------------|------------------|--------|
| Simple   | 1         | No                 | No          | Optional (no iteration) | 1 |
| Reflexion| 5         | No (single)        | No          | No               | 1 |
| DoT      | 5         | Yes (multi)        | No          | No               | 1 |
| DoT-Bank | 5         | Yes (multi)        | Yes (embedding retrieval) | No | 2 |
| ParamAgent| 5+5      | Yes (parametric)   | Yes (embedding retrieval) | Yes (LoRA/JSONL) | 2 |
